## Overview performance evidence

A three-tab browser profile observed 15 successful overview reads in approximately
32 seconds. The demo provider invalidates every ten seconds; each tab remained
within six reads including initial reads, initial SSE invalidation, demo events and
the polling fallback. Shell and page queries share reads within each tab.

A three-worker concurrent overview benchmark measured approximately 0.644 ms/op,
571,312 B/op and 10,431 allocs/op on the local ARM64 host. CPU and heap profiles
were collected under /tmp; runtime/allocator work dominated the flat CPU samples.
This measures demo throughput, not Kubernetes round-trip latency or total RSS.
No additional shared cache or weaker authorization freshness was introduced.

## Acceptance fixes

The first native run exposed two test-wiring failures. The desktop cluster test
used a removed popover CSS selector; it now selects the accessible workspace
dialog and confirmation checkbox. The browser runner now resolves a relative
live-overview fixture against the repository root, so both root and web-directory
invocations use the same real fixture. The live browser fixture is generated by
the required Kubernetes CI job and is never substituted with demo data.

Local Docker Hub timeouts and incompatible cross-platform installer helpers were
resolved by executing validation on native GitHub Actions runners. Earlier local
environment limitations are superseded by the native results above.

No release was published and no user's installed application was overwritten.
The macOS upgrade/rollback check operates only on isolated temporary bundles;
it does not claim a production GitHub release-to-release update was performed.
